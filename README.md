# Party Games · FFXIV 联机文字游戏

给 FFXIV 用的多人文字游戏平台：一个 Dalamud 插件 + 一台小服务器。建房、发 5 位房间码、3-20 人跨服开局。

目前有六个游戏：

| 游戏 | 人数 | 状态 |
|---|---|---|
| 谁是卧底 | 3-20 | 可用 |
| 俄罗斯轮盘 | 3-20 | 可用 |
| 堆雪球 | 3-20 | 可用（规则是本项目的设计，见下） |
| 词语接龙 | 3-20 | 可用 |
| 海龟汤 | 2-12 | 可用（内置题库） |
| 狼人杀 | 6-20 | 可用（MVP：狼人 / 平民 / 预言家 / 女巫） |

## 为什么需要一个服务器

Dalamud 插件是纯客户端的，本身没有任何联网能力。跨服、20 人、掉线托管这三件事，靠游戏内聊天都做不到（队伍上限 8 人、跨服组不了队、消息可伪造）。所以架构是这样：

```
插件 A（ImGui） ─┐
插件 B（ImGui） ─┼── WebSocket ──→ 游戏服务器
网页客户端     ─┘                  房间状态机 + 规则 + 计时
```

- **服务端权威**：所有游戏状态在服务器上。插件拿不到别人的词，改内存也作弊不了。
- **服务端驱动 UI**：服务器每次下发一个 `GameView`（标题、说明、玩家卡片、按钮、你的私密信息、截止时间），插件只负责画出来。
- **所以加一个游戏只需要写一个服务端文件**，插件一行都不用改 —— 俄罗斯轮盘就是这么加的，只新增了 `Games/RouletteGame.cs` 和注册表一行。

## 跑起来

### 0. 前置

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)（服务端和插件都要）
- 想用插件的话：XIVLauncher + 已启用的 Dalamud

### 1. 启动服务端

```powershell
dotnet run --project src/PartyGames.Server -c Release
```

默认监听 `http://0.0.0.0:5180`，WebSocket 在 `/ws`，健康检查 `/api/health`。

跨机器联机需要放行 5180 端口。放到公网建议前面挂一层带 TLS 的反向代理（那样插件里填 `wss://`）。

### 2. 先在浏览器里试玩（不用开游戏）

打开 `http://<服务器地址>:5180/`，多开几个标签页：一个「创建房间」，其他人拿房间码「加入」。

这是最省事的验收方式，也是和插件完全相同的协议实现。

### 3. 装插件

```powershell
.\build.ps1
```

如果被脚本执行策略拦住（`无法加载文件 ... 因为在此系统上禁止运行脚本`），这样跑：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

产物在 `src\PartyGames.Plugin\bin\Release\`：

- `PartyGames.dll` + `PartyGames.Protocol.dll` + `PartyGames.json` → 开发用
- `PartyGames\latest.zip` → 发布用

开发加载：把上面三个文件放进 `%APPDATA%\XIVLauncher\devPlugins\PartyGames\`，游戏内 `/xldev` → 加载开发插件。

游戏内输入 `/pg` 打开窗口，填服务器地址（本机就是 `ws://127.0.0.1:5180/ws`），连接，然后建房或输房间码。

## 玩法规则（当前实现）

**谁是卧底**：多数人拿同一个词，少数人拿近义词，没人知道自己属于哪边。每轮每人一句话描述自己的词，然后投票。平票本轮无人出局。投出的玩家公开自己的词和身份。所有卧底出局→平民胜；卧底人数 ≥ 平民人数→卧底胜。卧底人数按人数自动配：3-6 人 1 个，7-11 人 2 个，12-16 人 3 个，17 人以上 4 个。

**俄罗斯轮盘**：六格弹巢，房主可以在大厅里设 **1-5 发子弹**（默认 1）。轮流扣扳机，中弹出局后重新装填转轮。最后活着的人赢。每回合 30 秒，超时自动替你扣。子弹越多死得越快——3 发时基本每两下就有一个倒下。

**每轮（所有存活玩家各扣一次）结束后也会重新装填**，所以不会出现"第 6 枪必中"的死板感——子弹可能刚好落在没人轮到的格子里，这一圈就平安过去。日志里会显示「一圈扣完，重新装填」。

**堆雪球**：每人一个雪球，起始 1。轮流行动，三选一 —— 滚雪球（+2）、加固（+1）、砸人（-3，自己耗 2）。雪球涨到 12 会塌，归零也出局。最后活着的人赢；20 轮还没分出胜负就比雪球大小。每回合 25 秒，超时自动替你滚。

> 这个规则没有公认版本（查了没有标准玩法），是按名字设计的。你要是玩的是别的「堆雪球」，告诉我规则，改 `SnowballGame.cs` 一个文件就行，插件不用动。

**狼人杀**：夜里狼人杀一个人，预言家查验一个人，然后女巫决定救或毒（各一次）。天亮结算，白天自由发言（打完点「过」，所有人都过就提前投票），然后放逐投票，平票无人出局。狼人全出局→好人胜；狼人 ≥ 好人→狼人胜。死亡不公开身份，只有出局者自己知道。

**房主可在大厅调整**（创建房间后可见）：**狼人数**（1-19 随便设，开局按实际人数收紧，至少留 1 个平民）、**预言家**开关、**女巫**开关、**猎人**开关。不设时默认：6-7 人 2 狼，8-10 人 3 狼，11-14 人 4 狼，15 人以上 5 狼。

**好人阵营的职业**：平民、预言家、女巫、猎人。

- **预言家**：每晚查验一个人是狼人还是好人
- **女巫**：一瓶解药（救人）、一瓶毒药（毒人），各一次
- **猎人**：被狼刀或被投票出局后，可以开枪带走一个人；**被女巫毒死则不能开枪**。25 秒不选视为不开枪

> 这是 MVP 版：**没有猎人、守卫、警长竞选**。要加的话还是老规矩，只改 `WerewolfGame.cs`。

**词语接龙**：轮流说词，下一个词必须以上一个词的最后一个字开头，用过的词不能重复。接错、超时（30 秒）或点「认输」就出局，活到最后的赢。第一个词随便说。

**海龟汤**：房主当主持人，拿到汤底；其他人看汤面提问，主持人点「是 / 否 / 无关」回答。觉得自己猜到了就点「我要猜汤底」再写答案，主持人判定。猜对的人赢；主持人直接公布汤底则主持人赢。题库内置 8 个经典题。

**谁是卧底的四条硬校验**（描述阶段）：少于 3 个字、没有实际文字（纯符号数字）、直接包含自己的词、和别人说的一模一样——都会被驳回并提示原因。**"描述和词有没有关系"属于语义判断，纯规则做不到**，只能靠玩家互相抓。

## 积分（六个游戏都有）

**阵营制**（谁是卧底、狼人杀）：输的一方全员扣分，赢的一方不加也不扣。出局的人照样算在阵营里——你死了但你的阵营赢了，就不扣分。

**混战制**（俄罗斯轮盘、堆雪球、词语接龙、海龟汤）：只有赢家不扣分，其他人全扣。轮盘是"活到最后的那个人"，堆雪球是"雪球最稳的人"，接龙是"接住最后一棒的人"，海龟汤是"猜对的人"或"公布答案的主持人"。

所以一晚上的排名就是"谁扣得最少"。

默认规则：

| 游戏 | 起始分 | 输了扣 | 结算方式 | 大场规则 |
|---|---|---|---|---|
| 谁是卧底 | 3 | 1 | 阵营 | 无 |
| 狼人杀 | 3 | 1 | 阵营 | **超过 8 人时起始分变 2** |
| 俄罗斯轮盘 | 3 | 1 | 混战 | 无 |
| 词语接龙 | 3 | 1 | 混战 | 无 |
| 海龟汤 | 3 | 1 | 混战 | 无 |
| 堆雪球 | 3 | 1 | 混战 | 无 |

房主在大厅里就能调：起始分、输了扣几分、归零摇点开关、大场人数阈值、大场起始分，也能整体关掉积分。改动从下一局开始生效，已经在场上的分数不会倒推重算。

**积分归零 = 本轮结束**（核心机制）：

1. 每局打完，输的一方按阵营扣分，积分跨局累计
2. **谁的积分先被扣到 0，这一轮就到此为止**
3. 归零的人自动摇点：只有 1 和 2，**1 = 大冒险，2 = 真心话**，然后从惩罚库里抽一条具体内容
4. 多人同时归零就各摇各的
5. 房主在大厅点「清零重开」，积分按当前人数重新发一遍，开新一轮

大厅会明确显示：`本轮结束：XX 的积分用完了。XX 要 大冒险：学三声猫叫。（清点后由房主开新一轮）`

摇点可以在房主面板里关掉（`归零摇点` 开关）——关掉后归零仍然会结束本轮，只是不摇。

### 惩罚库（内容自己定义）

在 `%LOCALAPPDATA%\PartyGames\punishments.json`，两组分开写：

```json
{
  "dare":  ["学三声猫叫", "用最浮夸的语气夸右边那位三次"],
  "truth": ["最近一次说谎是什么时候？", "群里你最想道歉的人是谁？"]
}
```

- 第一次运行会自动生成一个示例文件，直接改里面的内容就行
- **改完保存就生效，不用重启服务端**（每次抽之前会检查文件有没有变）
- 某一组为空时，会用兜底文案（"临时想一个大家都满意的大冒险"）
- 抽中后写进日志和玩家卡片，同时记进对局历史，珊瑚统计「被罚过几次大冒险」也是按这个前缀数的

积分在**当前房间内跨局累计**：打完一局回大厅再来一局，接着算。服务器重启或房间关闭就清零——没有落盘，这是目前的设计。

大厅里有一个**积分榜**（按分数从高到低），结算画面也会带上，谁欠着什么惩罚一眼能看到。

## 我的战绩

**选择游戏界面**和**房间大厅**都会显示你自己的战绩，按游戏分组：

```
服务器在线 3 人 · 1 个房间
在线玩家：鹿岛渚咲、某某、某某某
我的战绩
狼人杀   3 胜 2 负（共 5 局）
俄罗斯轮盘  1 胜 4 负（共 5 局）
合计  4 胜 6 负（共 10 局）
```

没打过局时显示「我的战绩：暂无记录」。数据来自 `matches.json` 的历史记录（最多 300 局），按**昵称**匹配。所以：

- 换昵称（或换显示名）之前的记录不会算进来
- 想清空统计，删掉 `%LOCALAPPDATA%\PartyGames\matches.json` 即可

服务端每 4 秒给不在房间里的人推一次在线人数和战绩；一进房间就改由房间快照下发。

## 看谁在线

- **网页**：`/status` —— 全服在线人数、每个房间在玩什么、阶段、玩家列表（房主 / 已准备 / 掉线标灰），每 10 秒自动刷新
- **JSON**：`/api/status`
- **游戏内**：大厅标题会显示 `4/8 人在线 · 服务器共 12 人`（服务端下发，插件本来就渲染副标题，不用更新）

全服人数每 250 毫秒刷新一次；全员掉线的房间不会出现在列表里（那种房间要过几分钟才回收）。

## 珊瑚查询（按需，不刷群）

每局结束会**落盘一条记录**，但**不会自动往群里发**。珊瑚只在有人 @ 她问起时才去查——这样群里不会被战报刷屏。

查询走一个只读 MCP 工具（下面细说），她可以查：

- 最近几局谁赢了、谁扣分、谁被罚了什么
- 按人统计：参赛、胜率、累计扣分、大冒险/真心话次数
- 按游戏筛选（狼人杀 / 卧底 / 轮盘 / 雪球）、按房间筛选

历史记录落盘位置：

- `%LOCALAPPDATA%\PartyGames\matches.json`（最近 300 局，**重启不清空**）
- `%LOCALAPPDATA%\PartyGames\latest.json`（最后一局）
- `GET /api/history?limit=20`（HTTP）
- `.\query.ps1 -Limit 5`（命令行）

> 早先版本做过"每局自动播报到群"，现在默认关闭（`notify.json` 里 `enabled: false`）。
> 想重新打开就把 `enabled` 改回 `true` 并重启服务端；`dryRun: true` 可以只写日志不发送。

### 珊瑚按需查询（MCP 工具）

光靠"战报推进群"有个弱点：消息滚走了就查不到。所以另外挂了一个只读 MCP server，珊瑚可以直接按需查：

| 工具 | 用途 |
|---|---|
| `mcp__partygames__partygames_recent` | 最近 N 局：游戏、房间、胜负、每人积分、真心话/大冒险 |
| `mcp__partygames__partygames_leaderboard` | 按人汇总：参赛、输局、累计扣分、惩罚次数 |
| `mcp__partygames__partygames_status` | 数据是否可读、共几局、游戏服务器在不在线 |

它**只读 `matches.json`**，不依赖游戏服务端是否在跑，也没有写操作或进程控制。

实现落在 qq-bridge 一侧（不是本仓库）：

- `src/mcp-partygames.js` —— MCP server 本体
- `scripts/setup-dsh.mjs` —— 注册 `mcp-partygames`（已加入 `MANAGED_MCP_IDS`）
- `plugins/qq-agent-presets/qq-tool-restrict.mjs` —— 白名单加 `mcp__partygames__` 前缀

改完要重跑 `node scripts/setup-dsh.mjs desktop`（注意 profile 是 **desktop**，脚本默认是 web）。

## 已知限制

- **中文渲染没在游戏内验证**。插件用的是 Dalamud 默认字体，理论上带 CJK 字形；如果实际显示成方块，需要给插件加一个 Noto Sans CJK 字体图集。
- **没有自动重连**。掉线后点「回到房间」可以拿回座位，座位保留 2 分钟；对局中掉线超时视为出局。
- **服务器没有鉴权，也没有 TLS**。房间码就是唯一凭证，适合朋友之间自建自用。
- **没有旁观模式**，出局玩家留在房间里看结果。
- **房间码 5 位**（去掉了容易看错的 0/O/1/I），靠随机性避碰，没有密码功能。
- **狼人杀是 MVP 版**：没有猎人、守卫、警长竞选，死亡不公开身份，发言没有强制顺序。
- 服务端状态全在内存里，重启即清空。
